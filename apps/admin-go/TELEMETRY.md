# 设备上报防刷

`POST /telemetry/installations` 保留旧客户端的请求格式与成功响应。
匿名上报属于客户端声明，不能作为真实安装或唯一物理设备的证明。

## 记录规则

- 只有 `installation` 可以新增设备；按设备 UUID 幂等更新版本，不修改首次登记时间。
- 首次登记及重复登记都会尝试记录当天活跃，兼容旧客户端并发发送安装和活动请求。
- 未登记设备的 `activity`、`base_url_changed` 返回成功但不入库，避免旧客户端反复重试。
- 活动请求不修改安装版本或平台；活动平台使用已登记的平台。
- `activity` 按设备、UTC 日期去重。事务级 PostgreSQL advisory lock 串行处理同一设备，
  并发请求、进程重启和多实例不会产生当日重复记录。历史重复事件保留。
- 不按版本号封禁；已有旧版本与测试污染记录均不会被自动删除。

这些是相对于冻结 NestJS 基线的有意安全差异。无需 SQL 迁移；使用原表及
`deviceId, createdAt` 索引。旧镜像可继续读取全部数据。

## 限流

Redis 原子执行检查、计数和过期。请求预算在解析请求体前检查，设备预算在 DTO 校验后检查；
新增安装预算仅用于数据库中不存在的设备，正常更新版本不消耗新增配额。
所有配额均为从首个请求开始的固定时间窗口。被拒绝的请求不消耗其他预算。

| 环境变量 | 默认上限 |
| --- | --- |
| `TELEMETRY_GLOBAL_REQUESTS_PER_MINUTE` | 全局每分钟 2000 次请求 |
| `TELEMETRY_SOURCE_REQUESTS_PER_MINUTE` | 每来源每分钟 120 次请求 |
| `TELEMETRY_DEVICE_REQUESTS_PER_MINUTE` | 每设备每分钟 12 次请求 |
| `TELEMETRY_SOURCE_INSTALLATIONS_PER_HOUR` | 每来源每小时 30 个新安装 |
| `TELEMETRY_SOURCE_INSTALLATIONS_PER_DAY` | 每来源每 24 小时 100 个新安装 |
| `TELEMETRY_GLOBAL_INSTALLATIONS_PER_DAY` | 全局每 24 小时 1000 个新安装 |

阈值可按实际增长和共用出口情况调整；接受 1 至 1000000 的整数，不支持关闭限流。
IPv4 按地址计数，IPv6 按 /64 计数。Redis 键不直接保存 IP 或设备 ID。
超限返回 `429` 和 `Retry-After`；Redis 不可用返回 `503`，停止接收上报以保护数据库。
请求体最大 4 KiB，禁止压缩请求体，防止解压造成额外资源消耗。

## 代理配置

`TRUSTED_PROXY_CIDRS` 必须使用实际入口代理的明确 CIDR，建议单地址 `/32` 或 `/128`。
默认不信任转发头，拒绝 `/0` 配置。只有可信代理提供的 `X-Forwarded-For` 会生效；
从右向左取最近的不可信地址，忽略客户端伪造的前缀和 `X-Real-IP`。
后端端口应仅向代理网络或本机开放。代理地址变化时同步更新配置并重新部署 Go 服务。
不要直接信任整个互联网或不受控的容器网络，否则来源限流可以被绕过。

## 客户端测试隔离与验证

桌面 Rust 测试构建关闭安装、活动、服务器切换上报以及用量触发的后台上报线程。
测试隔离独立于版本号和服务端限流；正式客户端保持上报。

`Dockerfile` 的 `verify` 目标启动仅监听本机的临时 Redis，执行限流并发、过期、
错误请求、可信代理和故障关闭测试。额外的本地集成测试：

```sh
node apps/admin-go/scripts/telemetry-smoke.mjs
```

该脚本仅连接固定本地对照环境，需先运行更新后的 Go 镜像。
覆盖匿名活动不能创建安装、登记幂等、并发日活去重、版本更新、
伪造转发头、设备限流及新增安装限流，并在结束时删除本次生成的测试记录。

当前措施限制低成本批量刷量，尚未引入设备凭证或平台证明；
分布式攻击仍可能在配额内提交虚假安装，已知设备 UUID 也不应视为认证凭据。
