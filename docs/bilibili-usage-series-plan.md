# Codex Switch PC 端与手机端 Bilibili 四期教程规划

> 适用版本：Codex Switch v1.2.3（依据 2026-08-16 仓库功能整理）
>
> 用途：作为 Bilibili 合集的录屏、口播、章节、标题和简介参考。
>
> 合集规则：全系列只做 4 个视频。每期只围绕一个完整使用主题，相关子功能放在同一期的章节中讲完。

## 一、四期合集总览

| 期数 | 视频主题 | 观众看完能完成什么 | 建议时长 |

| 第 2 期 | PC 进阶篇：第三方模型与本地代理 | 接入 Provider，切换模型，并配置自动切号和并发路由 | 40～50 分钟 |

## 二、全系列统一录制方案

### 1. 每期固定结构

1. 前 20 秒展示本期最终效果，不先讲概念。
2. 用一句话说明本期解决的问题和适合人群。
3. 列出必要的前置条件，非必要配置不展开。
4. 按真实入口完成一次从设置到验证的操作。
5. 对危险或不可撤销的操作给出明显提示。
6. 用 2～3 个常见问题收尾，并预告下一期主题。

### 2. 录制前统一准备

- 准备 3 个专用测试账号：当前账号、备用账号、低额度账号。
- 准备一个可公开演示的第三方 API Key，并提前限制余额和权限。
- 准备两个测试会话、一个测试 Skill、一个可卸载插件和一张无文字水印的背景图。
- 手机篇至少准备一台保持在线的 PC，并让手机和 PC 登录同一个云端账号。
- 提前导出备份；删除、使用重置卡、批量消耗额度等操作只使用测试数据。
- 打开隐私模式，或在后期遮挡邮箱、手机号、密码、2FA 密钥、API Key、账号 JSON、备份文件和私人路径。
- 开始录制前关闭无关通知，准备好章节所需页面，避免在视频中长时间等待登录和下载。

### 3. 必须讲清的产品关系

- PC 端基础账号管理可以在本地使用，云同步是跨设备功能。
- 本地代理负责第三方模型、模型热切换、代理会话和 Token 统计。
- 接口显示的账号额度与本地代理统计的 Token 是两类不同数据。
- 手机端通过云端同步数据；远程切号时，目标 PC 必须在线。
- Codex Switch 是第三方开源软件，不是 OpenAI 官方产品。

### 详细录制流程

#### 1. 安装、首次启动与界面导航

**演示路径：** 项目发布页 → 选择系统安装包 → 安装 → 启动 Codex Switch。

**操作：**

1. 说明 Windows x64、Windows ARM64、macOS Apple Silicon、macOS Intel 和 Linux 包的区别。
2. 启动后展示空账号页面和当前版本。
3. 快速浏览“账户”“会话”“三方模型及中转”“Token 汇总”“Codex 主题”“插件”六个主页面。
4. 展示设置、通知、帮助和顶部入口搜索，但不在这里展开。

**口播重点：**

“第一次使用先把账号管理跑通。第三方模型、主题和插件会在后面的独立视频中讲。”

#### 2. 通过 OAuth 添加官方账号

**演示路径：** 账户管理 → 添加/更新账户 → 应用内登录。

**操作：**

1. 点击“添加/更新账户”，优先选择应用内登录。
2. 在授权窗口完成 ChatGPT 登录，等待账号自动加入列表。
3. 刷新该账号用量，确认授权有效。
4. 说明企业 SSO 或内嵌页面受限时，可改用默认浏览器。
5. 对同一账号重新授权一次，展示软件会更新原记录，不会重复添加。

**画面提示：** 登录过程中的邮箱、验证码和授权页面必须打码。

#### 3. 导入已有账号 JSON

**演示路径：** 添加/更新账户 → 多格式导入，或从剪贴板导入。

**操作：**

1. 使用脱敏测试文件演示导入标准 auth.json。
2. 简要说明还支持对象、数组、accounts 数组和逐行 JSON 等常见结构。
3. 再演示一次从剪贴板导入。
4. 导入后核对账号数量、邮箱和用量状态。
5. 展示一次格式错误，让观众知道应从哪里查看失败原因。

**安全提示：** 不要打开真实账号 JSON，更不要把文件内容贴在视频简介或评论区。

#### 4. 看懂账号列表和用量

**演示路径：** 账户管理 → 刷新单个账号 / 刷新全部用量。

**操作：**

1. 解释套餐、账号类型、主用量、次用量和重置时间。
2. 展示剩余比例、预设截止日期、错误状态和最后刷新时间。
3. 分别演示单账号刷新、全部刷新和只刷新重置卡。
4. 切换表格与卡片显示方式，并调整一次表格列顺序。
5. 说明“今日 Token”只有在本地代理运行并产生请求后才会出现。

**讲解边界：** 账号接口额度不等于代理统计的 Token 消耗。

#### 5. 管理备注和账号资料

**演示路径：** 双击备注，或账号更多操作 → 编辑账号资料。

**操作：**

1. 添加容易识别的备注，例如“主力”“备用”“测试”。
2. 设置预设可用截止日期。
3. 演示手机号、密码和账号绑定 2FA 的保存入口。
4. 用测试二维码导入 2FA，预览并复制一次验证码。
5. 返回列表，确认备注和截止日期显示正确。

**安全提示：** 账号资料属于敏感信息。录屏建议只填虚构内容，并保持隐私模式开启。

#### 6. 切换、热切换与取消使用

**演示路径：** 账号行 → 切换并重启 / 热切换 / 取消使用。

**操作：**

1. 在未启用本地代理时选择“切换并重启”。
2. 打开 Codex 发起一条测试请求，确认账号已切换。
3. 简短预告：启用本地代理后可以热切换，不需要重复重启客户端。
4. 演示“取消使用”，说明这只取消当前使用状态，不会删除账号。

**常见误区：** 列表里保存了账号，不代表 Codex 当前正在使用它；要看当前账号标记。

#### 7. 重置卡和批量管理

**演示路径：** 账号详情 → 重置卡；勾选多行 → 批量操作。

**操作：**

1. 刷新测试账号的重置卡，展示可用数量、发放时间和到期时间。
2. 展示“使用重置卡”的二次确认，但只在专用测试账号上执行。
3. 勾选多个账号，演示批量启用和批量停用自动切换资格。
4. 说明批量删除只删除本地记录，不会注销 ChatGPT 账号。
5. 只介绍“批量消耗额度”的用途和真实请求成本，不使用主力账号现场演示。

#### 8. 导出与恢复备份

**演示路径：** 文件 → 导出备份 / 导入备份。

**操作：**

1. 导出 .cs 备份文件。
2. 在测试环境删除一条记录。
3. 导入备份并确认账号、备注、用量和 Provider 数据按标识合并恢复。
4. 说明备份中包含可恢复凭据和 Provider 密钥，不能公开分享。

**保存建议：** 放在加密磁盘、密码管理器附件或受控的离线备份目录。

#### 9. 自动刷新、托盘与悬浮用量球

**演示路径：** 设置 → 自动刷新 / 悬浮用量球；系统托盘图标。

**操作：**

1. 开启全局用量自动刷新并设置合理间隔。
2. 等待一次刷新，确认“最后更新时间”发生变化。
3. 最小化主窗口，从系统托盘打开控制台和切换测试账号。
4. 开启悬浮用量球，在圆球与玻璃信息卡之间切换。
5. 演示拖动、悬停展开、左键刷新和右键快捷菜单。

**讲解重点：** 刷新间隔不要设置过短；悬浮球是查看当前额度的快捷入口。

#### 10. 云同步与误删恢复

**演示路径：** 设置 → 云同步服务器；顶部云端 → 注册/登录 → 云同步。

**操作：**

1. 使用可用的云端服务注册或登录。
2. 手动同步一次，确认本机账号和 Provider 完成合并。
3. 在另一台 PC 或手机上确认数据出现。
4. 删除一条专用测试记录，从云同步回收站恢复。
5. 展示修改密码和退出登录入口。

**安全提示：** 开启同步会把完整账号凭据和 Provider 密钥发送到所配置的服务器，只连接自己信任的服务。

### 本期常见问题

- 内嵌登录失败：改用默认浏览器，并检查本地回调端口是否被占用。
- 切号后客户端仍显示旧状态：完全重启 Codex，再发起新对话验证。
- 刷新用量失败：先重新授权账号，再检查 Codex Switch 自身的网络代理设置。
- 导入备份后出现旧数据：导入采用合并恢复，先用专用测试环境演示。

### 详细录制流程

#### 1. 启动和停止本地代理

**演示路径：** 顶部本地代理开关 → 启动代理 / 停止代理。

**操作：**

1. 展示默认端点 127.0.0.1:15722/v1。
2. 启动代理，完整保留“准备客户端、更新配置、同步会话、重启客户端”的进度。
3. 使用官方账号发送一次测试请求，证明请求已经经过代理。
4. 停止代理，等待官方配置和非代理会话恢复。

**讲解重点：** 第一次启动或停止可能需要处理较多会话文件，不要在进度中途强制退出。

#### 2. 使用预设添加 Provider

**演示路径：** 三方模型及中转 → 添加 → 添加模型预设。

**操作：**

1. 快速浏览常用预设，不逐个展开。
2. 选择一个实际测试的云端 Provider，填写节点和 API Key。
3. 拉取模型列表，选择当前模型并保存。
4. 再用 Ollama 或 LM Studio 简短说明本地模型地址通常需要包含 /v1。
5. 保存后核对 API 格式、模型和就绪状态。

**讲解重点：** 节点、计费方式和 API Key 必须匹配；不要为了展示而暴露真实密钥。

#### 3. 添加自定义 Provider 和中转站

**演示路径：** 三方模型及中转 → 添加 Provider / 添加中转站。

**操作：**

1. 自定义 Provider：填写名称、Base URL、API Key、模型列表和当前模型。
2. 选择 OpenAI Responses 或 Chat Completions 转换格式。
3. 按需设置图片模型、上下文窗口和推理级别。
4. 演示 New API 或 Sub2API：填写站点地址和 API Token，自动拉取模型。
5. 配置可选余额查询后保存，并发送一次包含工具调用的测试请求。

**讲解边界：** 接口名称兼容不代表所有能力都兼容，文本、流式输出、工具调用和图片能力要分别验证。

#### 4. 切换 Provider、模型和控制方式

**演示路径：** Provider 行 → 热切换；模型下拉框；模型控制方式。

**操作：**

1. 从官方账号热切换到测试 Provider。
2. 在同一个 Provider 内切换一次模型。
3. 对比“由 Codex 控制模型”和“由 Codex Switch 固定模型”。
4. 发起测试请求，在当前状态栏核对目标。
5. 切回官方账号，展示全链路切换结果。

#### 5. 查看余额和 Token

**演示路径：** Provider 列表 → 刷新余额；Token 汇总。

**操作：**

1. 刷新测试 Provider 的 API 余额或钱包余额。
2. 解释“无限额度”“未配置”和“查询失败”三种状态。
3. 连续发起几次代理请求，查看今日 Token 和累计 Token。
4. 打开 Token 汇总，快速展示输入、输出、推理和缓存分类。

**讲解边界：** 余额来自上游接口，Token 来自本地代理；Token 统计不等于上游完整账单。

#### 6. 配置额度耗尽后自动切号

**演示路径：** 顶部自动切号 → 开启；账号行 → 启用或停用自动切换。

**操作：**

1. 准备至少两个可用账号，并开启自动切号。
2. 指定哪些账号可以参与自动切换。
3. 开启自定义优先级，说明数字越小越优先。
4. 按需配置 401、402、403 等状态码触发自动停用。
5. 选择一个 Provider 作为所有官方账号不可用时的兜底目标。
6. 用低额度测试账号触发一次切换，确认当前请求只自动重试一次。

#### 7. 开启多账号并发路由

**演示路径：** 账户管理 → 多账户并发。

**操作：**

1. 让多个账号拥有自动切换资格，再开启多账户并发。
2. 新建三个不同对话，观察它们被分配给不同账号。
3. 在原对话继续追问，确认同一对话始终使用原账号。
4. 关闭并发并说明：并发是按对话分配，不会拆分单次请求。

#### 8. 官方登录态账号和图片账号

**演示路径：** 账号行 → 激活官方登录态；账户页或 Provider 页 → 图片账号。

**操作：**

1. 选择一个兼容 OAuth 的账号作为官方登录态。
2. 说明“官方登录态”与“当前对话请求账号”不是一个概念。
3. 选择另一个支持图片能力的 OAuth 账号作为图片账号。
4. 保持当前对话使用 Provider，发起一次图片测试，核对图片路由没有改变普通对话目标。
5. 演示取消官方登录态和清除图片账号。

#### 9. 局域网代理和上游 Codex Switch

**演示路径：** 本地代理 → 监听局域网；三方模型及中转 → 添加上游 Codex Switch。

**操作：**

1. 开启局域网监听并生成高强度 API Key。
2. 在另一台设备填写 PC 局域网 IP、端口和 Bearer Token。
3. 发起测试请求，确认远程设备必须鉴权。
4. 简要演示把另一台 Codex Switch 的 /v1 地址作为上游。
5. 演示结束后关闭局域网监听。

**安全提示：** 不要把代理端口直接暴露到公网，不要使用弱密钥，也不要展示路由器端口转发。

#### 10. 代理会话和诊断日志

**演示路径：** 账户或 Provider 顶部 → 查看代理会话；工具 → 导出日志。

**操作：**

1. 查看对话标题、目标账号或模型、上下文 Token 和活动状态。
2. 打开请求详情，查看模型、推理级别、首次响应、总耗时和 Token。
3. 制造一次可控的 Provider 错误，结合状态码定位原因。
4. 导出结构化诊断文件，说明分享前仍要人工检查敏感内容。

### 本期常见问题

### 详细录制流程

#### 1. 安装 App 与登录

**前置条件：** PC 已登录云端并保持运行；手机可访问同一个云端服务。

**演示路径：** PC 帮助菜单或项目发布页 → 下载 Android App → 登录页。

5. 回到 PC 手动同步一次，为后续演示准备数据。

**画面提示：** 手机系统键盘、验证码通知和授权页面都要检查是否泄露隐私。

**演示路径：** 账号卡片 → 切换 → 选择目标设备。

**操作：**

1. 保持两台测试 PC 在线，显示它们当前使用不同账号。
2. 在手机选择目标账号。
3. 在设备列表中只选其中一台 PC。
4. 等待切换成功，观察目标设备的当前账号变化。
5. 在目标 PC 新建对话验证；再确认另一台 PC 没有变化。

**讲解重点：** 命令按设备下发，不会把同一用户的所有电脑一起切换。

**演示路径：** 设备 → 选择设备 → 代理登录态账号。

**操作：**

2. 下拉刷新，观察在线状态变化。
3. 为在线 PC 选择一个兼容 OAuth 的官方登录态账号。
4. 等待 PC 更新并重启 Codex，分别在手机和 PC 验证。
5. 让一台测试 PC 退出桌面端，再删除离线设备。

**讲解重点：** 在线设备不能删除；官方登录态账号也不等于普通对话请求账号。

#### 7. 管理账号资料和手机 2FA

**演示路径：** 账号详情 → 账号资料；底部导航 → 2FA。

**操作：**

1. 编辑测试账号的备注、预设截止日期和手机号。
2. 演示密码显示、隐藏和复制，但只使用虚构数据。
3. 在账号资料中扫码导入绑定 2FA。
4. 进入独立 2FA 页面，再添加一条测试 Authenticator 记录。
5. 演示搜索、复制验证码、编辑和删除。
6. 在设置中说明 2FA 自动云同步默认关闭；如主动开启，敏感密钥会同步到服务器。

#### 8. 自动刷新、密码和退出登录

**演示路径：** 设置 → 刷新设置 / 登录密码 / 退出登录。

**操作：**

1. 设置合理的自动刷新间隔，并返回账号页确认。
2. 说明应用保持前台时会按间隔刷新，也可以随时手动刷新。

3. 在手机浏览器登录 Web 页面。
4. 演示查看用量、重置卡、远程切号和设备状态。
5. 说明 Web 页面功能比 App 精简；需要添加账号、编辑私密资料或管理 2FA 时使用 App。
