# 手机任务验收

原生 App 与 Web 聊天中，有文件改动的已结束回复会在「已编辑文件」卡片中、「审核」左侧显示「验收结果」入口，不再单独展示「任务验收」卡片。点击「验收结果」可以查看改动、运行项目验证、逐行留言、预览恢复影响，以及查看 GitHub PR / CI。原有「审核」diff 入口和工具菜单里的 Git 入口继续保留。

## 项目验证

- build、lint、test 分别显示未运行、运行中、通过、失败、已中断或结果已过期。聊天里 AI 声称「测过了」不会产生验证记录。
- 验证针对会话项目目录中的**当前代码**，包括其他会话尚未提交的改动；本轮 diff 则是原任务的历史改动。
- 支持当前目录 `package.json` 中的 build / lint / test 脚本；没有 package.json 时识别 Cargo 或 Go 项目，分别运行 build / clippy / test 或 build / vet / test。未配置的项目验证显示未运行，不允许从手机输入任意验证命令。
- 点击运行后展示具体命令，确认后在电脑上执行。命令使用当前用户权限，可能修改文件、下载依赖或运行项目自己的脚本。每个项目目录同一时间只运行一项验证。
- 每项验证的最新记录保存于电脑应用数据目录。关闭手机抽屉或断开手机连接不会取消已启动的命令。电脑端进程重启后，未完成记录显示「验证已中断」。本功能不等同于独立后台 AI 服务。
- 单次命令最长运行 30 分钟；标准输出和错误输出各最多保留 64 KiB，超出部分会提示省略。退出码决定通过或失败。

验证开始和结束时记录代码指纹，覆盖 HEAD、分支、暂存区、工作区 diff 和未被忽略的未跟踪文件内容。当前指纹变化，或验证期间前后指纹不同，结果显示过期；结束时无法核实版本则显示中断。断线或读取失败时不展示旧记录为当前结果。

这不是隔离的、可重现的构建证明：忽略文件、依赖安装状态、外部服务和环境变量不在版本指纹内，执行期间短暂修改后又还原的文件也无法由前后指纹证明。子模块及设置了 assume-unchanged / skip-worktree 的文件会阻止版本核验。未跟踪文件最多 2,000 个、合计 64 MiB，链接文件不参与验收。大型仓库可以先在电脑上整理文件后再验证。

## 留言与恢复

在验收 diff 的某一行点击「留言」，填写意见后发送到原会话。消息包含原任务、文件、修改前或修改后的行号和当时的代码。删除行和重命名文件保留原文件位置。发送结果不确定时保留意见，提示先检查会话，避免重复发送。

「预览恢复影响」只准备反向修改，不改动项目文件。预览列出受影响文件和冲突状态；有冲突时不能确认。确认时重新核对这些文件的内容，预览后的新改动会使确认失效。执行阶段也检查文件并保留已有的非冲突改动，不进行整仓库重置。外部编辑器不受应用锁控制，检查和写入之间仍有很短的竞争窗口。

## PR 与 CI

电脑需安装 GitHub CLI (`gh`)、完成登录并具有仓库权限。点击「刷新 PR 与 CI」读取当前分支的打开 PR、提交版本和检查状态。CI 与本地代码版本不同，或本地还有未提交修改时，界面提示版本不一致。

先通过保留的 Git 入口提交并推送，再填写标题、说明和可选目标分支，确认创建**草稿 PR**。创建前核对当前代码与已推送分支一致，不自动推送或 fork。已有打开 PR 时返回该 PR；创建结果不确定时提示先刷新状态。当前支持 GitHub CLI 选定的仓库，不覆盖所有跨 fork 工作流。

## 实现与验证

两端共享 `shared/remote-chat/taskReview.ts`、`useTaskReview.ts` 和 `TaskReviewContext.tsx`。桌面侧通过现有 Git / undo 命令执行，文件和进程操作放在工作线程。GitHub 网络请求不占用本地 Git 操作锁。

Rust 回归覆盖真实项目脚本退出码、版本变化、重启后中断、隐藏跟踪标记、PR 版本校验、恢复预览与后续修改保护。前端回归覆盖两端状态和入口、单次轮询、断线及发送结果不确定；Web 端到端用例覆盖手机和桌面宽度下的验收、留言、恢复冲突和模拟 PR / CI，不会创建真实远程 PR。
