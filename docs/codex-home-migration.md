# Codex Home 会话迁移验证

会话管理工具栏在“移动到回收站”右侧提供“对话迁移”。选择会话后，可将其移至其他已配置的 Home，保留对话记录和项目路径。目标已有相同会话 ID 时跳过，不覆盖目标会话。

迁移前应结束所选会话中的任务，并使用目标 Home 启动一次 Codex，初始化会话数据库。

## 日志冲突修复

两个 Home 的 SQLite 日志 ID 分别自增，相同数字不代表同一条日志。直接恢复原 ID 会触发 `INSERT OR REPLACE`，覆盖目标其他会话的日志。

跨 Home 恢复时，仅在内存中的迁移副本清空日志 ID，由目标数据库分配新 ID。原始备份仍保留源 ID，失败时可以完整还原源会话。

## 2026-09-16 关联会话迁移修复

用户批量迁移时出现“请将有关联的会话一起选择后迁移”。旧实现将导出和回收站的选中范围检查直接用于跨 Home 迁移，隐藏子会话、已经失效的子会话关系和目标已有的父会话都会阻断迁移。只选择数据库中记录的子会话时，还可能漏掉同组会话。

迁移现在会结合会话记录及父子关系自动收集关联会话，包括归档记录、多级子会话和分支来源。已经不存在的子会话不会阻断迁移；真正缺失的共享历史仍会在写入前报错。目标已有的会话保持不变，仍被源目录中保留会话使用的历史也保留在源目录。

所有会话先备份并校验，再写入目标。全部目标文件就绪后才恢复会话状态，全部恢复成功后才移除源会话。任何一项失败都会尝试回滚整批，保留原始关系、日志和历史；回滚未完成时保留可恢复备份。

回归覆盖：50 条所选会话与隐藏子会话、重复会话、失效关系、多级共享历史、归档子会话、目标仅剩索引但缺少历史、准备完成后目标新增重复会话，以及目标恢复失败和源清理失败时的整批回滚。旧实现运行新增用例时有 6 项失败，与用户报告的关联会话报错一致。

自动回归：独立工作树 Rust 1207 项通过、5 项忽略；合入当前代码后完整 Rust 回归 1220 项通过、5 项忽略。两轮格式检查、严格 Clippy、前端迁移及回收站 5 项测试、TypeScript/Vite 生产构建均通过；独立工作树的 Windows 可执行文件构建通过。本轮测试证据位于 `.codex-tmp/migration-relations/`。
